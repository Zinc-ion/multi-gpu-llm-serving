## 三、必须实现的行为

### 1. 独立实例与资源隔离

P、D 必须能够独立启动、配置、关闭和重启。

处理当前固定 rendezvous 地址和固定共享内存名称的问题：

- 不同实例使用独立端点和资源标识。
- 一个实例退出不能清理另一个实例的资源。
- 明确物理 GPU、可见逻辑设备与实例内部 rank 的关系。

本轮使用 TP=1。
P/D 是独立实例，不把它们作为同一个 TP 组的两个 rank。

### 2. 请求协议和首 token 交接

明确跨实例请求 ID、实例内 sequence ID、token 进度、位置偏移、block 描述及采样元数据。

设计时必须明确：

- 首个输出 token 由谁采样和发送。
- 交接时哪些 token 已经具有 KV。
- D 下一步处理哪个 token、使用哪个 position。
- completion 计数和剩余输出预算如何延续。
- `max_tokens`、多 EOS、`ignore_eos` 和总长度上限如何保持一致。
- 首 token 即 EOS 或 `max_tokens=1` 时怎样结束并释放资源。

不能直接假设现有 `Sequence` 的 TP 序列化就是完整 PD 协议。
新增字段和状态必须有实际使用路径。

### 3. 整块同步 KV 传输与恢复

Prefill 完成后，传输该请求的 KV，作为 B2 的基础实现。

正常路径必须真实完成：

P 生成 KV → D2H → 主存及进程间交接 → H2D → D 恢复 → 继续生成。

不能以 D 重算整个 prompt 代替正常 KV 交接。

明确：

- KV shape、dtype、层数、KV heads 和 block 布局。
- 有效 token 范围与末尾不满 block 的处理。
- P、传输 buffer、D 各自的资源所有权。
- 复制完成、恢复成功、确认及释放的时机。

D 必须分配自己的 block 并建立本地 block table。
P 的物理 block ID 不能直接当作 D 的物理 block ID。

数据路径不依赖 P2P/NVLink。
本地同卡双进程也必须有独立 KV 存储，并经过真实主存交接；只传 GPU tensor 引用不能算完成验证。

待传输请求和传输 buffer 必须有明确容量边界。

### 4. 生命周期与故障回收

通过真实可达路径处理：

- 排队、prefill、传输等待、恢复、decode 阶段的取消。
- 交接超时。
- 对端退出。
- D 容量不足及恢复失败。
- 重复交接、重复确认。
- 取消后的迟到消息。
- 实例关闭后的资源清理。

保证请求不会重复执行或重复终结，资源不会泄漏或重复释放。
检查存活侧能继续处理后续请求。

重试和恢复必须有明确语义，不添加无限重试或无界状态记录。

### 5. HTTP 与测量接入

复用现有 OpenAI 兼容服务能力，提供可运行的 PD 服务入口。
先使用固定 P/D 目标，不提前实现 M8 的动态负载均衡。

核对流式输出、usage、finish_reason、客户端断开和取消传播。
首 token 不能重复发送，completion token 不能遗漏或重复计数。

按请求 ID 记录：

- 实际传输字节数。
- P 处理、传输、D 恢复耗时。
- 首 token、第二个 token 和完成/失败事件。
- 必要的资源占用与释放信息。

明确计时起止和包含的阶段。
不能把 CUDA 异步提交耗时直接写成传输完成耗时。
复用现有测量能力，避免向正常 decode 热路径加入无必要同步。

## 四、本地验证

### 1. CPU 与协议验证

通过真实对象和公开接口验证：

- 元数据、进度、block 映射与有效长度。
- 多请求独立性。
- 取消、超时、重复交接、恢复失败。
- 请求归属和 KV 资源守恒。

PD 的传输中状态应纳入不变量，不能机械套用旧 waiting/running 断言。

### 2. 真实 GPU、多进程验证

使用可复现的 tiny Qwen3 checkpoint，或已有且容量允许的小模型。

独立启动 P、D 进程，同驻本机 GPU，并设置明确的小规模 KV 预算。
完成真实 prefill、主存交接、恢复和 decode。

与同模型、精度、输入及采样设置下的共置参考比较：

- greedy token 逐 token 一致。
- logits 在相同前缀下比较。
- 比较前固定本地测试容差和理由，不为通过而事后放宽。

优先验证 FP32 和 BF16。
本地测试容差不等于 14B 正式验收阈值。

### 3. 必须覆盖的边界

覆盖短 prompt、跨 block、末尾不满 block、多请求、不同输出长度、EOS、`max_tokens=1`，以及恢复后继续生成并跨 block。

通过真实取消、关闭连接和受控终止测试子进程验证回收。
不要仅靠篡改内部状态或 monkeypatch 抛异常证明防御代码存在。

### 4. M3 回归

运行现有 paged/chunked prefill 与 CUDA Graph 回归。
M5 的 D 侧恢复至少在真实 GPU 上验证 eager 和 graph 路径。

不支持的组合明确拒绝并说明原因，不静默切换模式。

### 5. 执行并记录验证结果

运行相关专项测试及：

```bash
CUDA_VISIBLE_DEVICES='' uv run python -m pytest -q
CUDA_VISIBLE_DEVICES=0 uv run python -m pytest -q -ra
```

设备编号以实际检查为准。

记录命令、环境、passed/failed/skipped、跳过原因及日志位置。
不能把本机具备条件的关键 GPU 路径全部 skip 后宣称完成。
