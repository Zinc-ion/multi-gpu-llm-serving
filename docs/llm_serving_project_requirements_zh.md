# 单机多卡 LLM 推理系统项目需求

## 1. 项目定位

### 项目名称

**单机多卡 LLM 推理系统与性能优化**

标题不使用基座仓库名称。项目说明中应如实写成“基于开源轻量推理框架进行二次开发”，并保留上游 Apache-2.0 许可证和版权信息。

### 最终简历目标稿

以下内容是完成对应模块并通过验收后的目标稿，`XX` 必须用实际测量结果替换，未完成的功能不能提前写入简历。

**项目描述：**

面向 Qwen3.8-27B 文本生成场景，基于开源轻量推理框架进行二次开发，在单机多卡环境构建支持张量并行和 Prefill/Decode 分离的推理系统，围绕 KV Cache、混合注意力状态、低精度推理和端到端性能开展正确性验证与优化。

**个人工作：**

- 修复并验证张量并行权重分片、并行线性层和 KV Cache 生命周期问题，建立单卡/多卡 logits 与生成结果的一致性测试。
- 适配 Qwen3.8-27B 文本推理路径，支持其 Gated DeltaNet 线性注意力与全注意力混合结构，管理 KV Cache、递归状态和请求生命周期。
- 在 4 张 RTX 4090 48GB 上实现 `2 卡 Prefill + 2 卡 Decode` 的单机 PD 分离，完成 KV、线性注意力状态和请求元数据的传输、恢复与异常回收。
- 接入并评估 FP8 或其他低精度推理路径，对比 BF16 基线的显存占用、TTFT、TPOT、输出质量和吞吐变化。
- 使用 PyTorch Profiler、Nsight Systems 和请求级压测工具定位计算、通信、状态传输及 CPU 调度热点，针对实测瓶颈完成 `XX` 优化。
- 在相同模型、精度、输入输出长度和请求分布下，将 `XX` 指标从 `XX` 优化至 `XX`，并记录 P95/P99 延迟、输出吞吐、峰值显存和失败率。

**技术栈：**

Python、PyTorch、CUDA、Triton、NCCL、Transformers、PyTorch Profiler、Nsight Systems。

## 2. 硬件和部署约束

- 服务器：5 张 NVIDIA GeForce RTX 4090，单卡可见显存 `49140 MiB`，驱动 `580.178.04`。
- GPU 拓扑：GPU0-2 位于一个 NUMA/PCIe 域，GPU3-4 位于另一个 NUMA/PCIe 域；跨域连接为 SYS；`nvidia-smi topo -p2p r/w` 当前显示 `CNS`。
- 第一版主部署：GPU0/1 作为一侧、GPU3/4 作为另一侧，使用 4 张卡完成 `2P + 2D`；GPU2 作为备用和对照卡。
- 5 卡 `3P + 2D` 暂不作为主方案。三卡 TP 是否满足目标模型的头数、权重和状态切分约束，需要单独证明，不能仅凭显存总量决定。
- 模型和实验数据存放在 `/Data2/zincion`，避免占用根分区；详细硬件记录见 [server_hardware_2026-11-09.md](./server_hardware_2026-11-09.md)。

## 3. 基座已有能力与归属边界

上游仓库已经提供以下基础代码：

- Qwen3-0.6B 和 Llama-3.2-1B 的模型实现及权重加载入口。
- Prefill/Decode 推理流程、请求调度、KV block 管理和 CUDA Graph 路径。
- Prefill FlashAttention、Decode Paged Attention 的 Triton 实现及独立 kernel benchmark。
- NCCL 进程组、进程 worker、张量并行线性层和简单 TPS 对照脚本。

这些内容可以作为项目基座和系统背景，但不能直接表述为本人的新增实现。个人贡献必须落在后续改造、缺陷修复、测试和可复现实测结果上。

## 4. 必须开发的模块

### M0：基线、许可证和可复现入口

- 固定上游基线 commit，记录本地分支和所有改动来源。
- 保留 Apache-2.0 许可证和上游版权信息。
- 增加统一配置文件，避免模型结构、并行规模和缓存容量散落在入口脚本中。
- 固定模型 revision、dtype、tokenizer、采样参数、随机种子和测试输入。
- 产出：基线运行说明、功能清单、版本信息和最小复现命令。

### M1：调度和 KV Cache 正确性

- 修复 block 引用计数、释放后的 hash 元数据和 block 生命周期问题。
- 验证 allocate、append、deallocate、抢占、取消、EOS 和 OOM 回收。
- 确保等待队列、运行队列和已调度序列守恒，不出现请求丢失或无进展循环。
- 补充真实 BlockManager 测试，减少只使用 MagicMock 的测试。
- 验收：活动引用归零，free/used block 守恒，失败和取消不泄漏。

### M2：模型配置和 Qwen3.8-27B 适配

- 从模型 config 读取结构参数，不再依赖 Qwen3-0.6B 的硬编码分支。
- 先实现文本路径，暂不扩展视觉编码器和多模态输入。
- 增加 Qwen3.8-27B 的混合层结构：Gated DeltaNet 线性注意力、全注意力、对应 FFN、RoPE 和输出头。
- 管理全注意力 KV Cache、线性注意力递归状态和卷积状态；明确每个状态的 dtype、布局、生命周期和 batch 映射。
- 验收：单序列、多序列、不同长度和多步 greedy 结果与参考实现满足预先固定的误差阈值。

### M3：张量并行和多卡正确性

- 修复 checkpoint loader 绕过并行层 `weight_loader` 的问题。
- 核对 Column/Row/QKV/Merged Linear 的权重、bias、reduce 和 shard 方向。
- 增加 TP=2/4 的参数分片、通信和输出一致性测试。
- 支持独立 GPU 映射，不能把物理 GPU 编号、rank 和本地 rank 混为一谈。
- 验收：多卡参数分片无未加载参数；TP 输出与单卡或参考 logits 一致；记录通信时间和峰值显存。

### M4：Prefill/Decode 分离

- 将 Prefill 和 Decode 拆成可独立启动、独立配置和独立生命周期的实例。
- 设计请求协议，传输请求 ID、token 进度、位置偏移、block/state 描述和采样元数据。
- 传输并恢复全注意力 KV、线性注意力状态和必要的卷积状态。
- 使用实例独立的 rendezvous、共享内存或传输 buffer 名称，不能复用固定的全局 `myvllm` 名称。
- 处理超时、取消、失败、重复传输、状态释放和 Decode 侧恢复失败。
- 验收：分离前后 token 结果一致；单请求、并发请求、取消请求和异常退出均无状态泄漏；记录状态传输大小、延迟和吞吐。

### M5：量化和低精度路径

- 先完成 BF16 基线，再选择一种可在 RTX 4090 上实际运行的 FP8 或其他低精度路径。
- 明确是“接入并评估官方权重”还是“自行实现量化/校准/内核”，简历措辞与实际工作保持一致。
- 对比权重显存、KV 显存、TTFT、TPOT、输出吞吐和模型质量误差。
- 验收：相同输入和解码配置下，结果误差、NaN/Inf、显存峰值和吞吐均有记录。

### M6：Profiling、压测和优化

- 记录 schedule、prepare、H2D、forward、sampling、D2H、postprocess 和状态传输阶段。
- 建立固定到达计划和请求回放，记录排队时间、首 token 时间、逐 token 时间和完成时间。
- 统一指标口径：TTFT、TPOT、ITL、输出 token/s、请求吞吐、P95/P99、峰值显存、失败率和状态传输开销。
- 使用 PyTorch Profiler 定位阶段热点，再用 Nsight Systems 验证 CPU/GPU 时间线、同步、通信和 kernel 空隙。
- 每次只改变一个主要变量，保留原始数据、配置、trace 和统计脚本。
- 验收：优化前后使用同一模型、精度、输入输出长度、请求分布和硬件分组；只有端到端数据改善时才写入简历。

### M7：部署和文档

- 提供单卡、TP=2/4、2P+2D 的启动脚本和配置样例。
- 记录 GPU 映射、NUMA 绑定、环境版本、模型路径和数据目录。
- 为每个实验保存原始 JSONL/CSV、trace、日志和结论。
- 明确哪些代码来自上游、哪些是修复、哪些是新增实现。

## 5. 实施顺序

1. 本地完成 M0/M1 的配置整理、调度和 block 生命周期测试。
2. 用小模型完成 M3 的 TP 正确性，先证明权重分片和通信正确。
3. 适配目标模型的文本路径，完成 M2 的参考结果对照。
4. 在 BF16 下完成 M4 的最小 2P+2D 正确性闭环。
5. 完成 M5 低精度对照，再进行 M6 profiling 和端到端优化。
6. 最后整理 M7 的复现入口、数据和简历指标。

## 6. 简历事实边界

- 原仓库已有的分页注意力、基础调度器、基础 TP 代码和 kernel benchmark 只能写成项目基座或系统已有能力。
- “支持 Qwen3.8-27B”“实现 PD 分离”“支持 FP8”“提升 XX%”只有在代码、测试、日志和对照数据齐全后才能写。
- 如果最终只完成 TP、多卡正确性和 profiling，应删去 PD 和量化的完成式表述，改写成实际完成的模块。
- 所有 `XX` 数值都必须来自同硬件、同模型、同精度和同负载的可复现实验。
