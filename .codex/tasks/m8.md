# 单机多卡推理框架：当前开发与交付任务

2026-11-17 调整范围，2026-11-18 更新 GPU 实测。项目名称为 **基于 mini-vLLM 的单机多卡大模型推理框架开发**，目标模型固定 **Qwen3-14B**。本文件覆盖此前“深入优化 KV 交接”、强制四卡组合、完整性能研究与多 agent 的冲突要求；[需求](../../docs/llm_serving_project_requirements_zh.md)、[验收](m8_acceptance.md)、[支持矩阵](../../docs/inference_optimization_overview_zh.md) 和 [本轮实测](../../docs/l40s_acceptance_2026-11-18_zh.md) 为当前依据。

## 目标与边界

主 agent 直接推进：实现梳理 → 必要修复 → 功能与正确性验证 → 支持范围 → 小规模端到端测量 → 简历与讲解材料。保留已有修改和扩展代码，比赛项目不在本轮范围。允许借鉴 vLLM/SGLang，保留许可证与来源。

分别验收 BF16 TP1、BF16 TP2、BF16 bulk P/D、FP8 KV TP1；TP2 双卡、1P1D 双卡即可做对应基本验收。TP2＋PD、FP8＋TP2、FP8＋PD 等组合只记录实际状态，不要求全补齐。只有简历需要“四卡部署”时才集中完成真实四卡记录；不强制一个 TP2 P＋两个 TP1 D 作为所有功能的共同前提。

不要求寻找新优化点、逐层流水收益、战胜 vLLM、完整消融、最大 goodput、Math500 或大型外部性能对比。保留逐层传输等代码，仅在容易验证时记录。仍需另采一段短 profile，描述计算、通信与等待。

## 已核对事实

- 实现基线 `c22beef` 已包含严格 TP loader、多 rank 命令与回收、TP2 P→TP1 D bulk 全头汇总、FP8 data＋scale 与 prefill 计算模式。代码存在和 CPU 通过不等于目标 GPU 验收。
- TP2 原 tiny BF16 失败已在 L40S 复现并重放：权重/输入分片精确一致，分片 BF16 GEMM 后求和复现首个 `o_proj` 的全部 113 个差异。CUDA BF16 TP>1 Row 保留 FP32 部分积与归约后，原 GPU FP32/BF16 两项通过，未改输入、seed、容差或判定。
- Qwen3-14B BF16 TP1 六组各 16 输出对 HF greedy 6/6，同前缀重算 top1 为 95/96；修复后独立 TP2 六组生成及同前缀 top1 均一致。正式 logits 容差未定，仍有较大非 top1 logits 误差，不能称通用数值等价。PD/FP8 的历史 tiny 数字与本轮 14B 分开记录。
- FP8 实际为运行时 KV 量化、E4M3FN 存储、token/head FP32 scale、attention 反量化与 PD 传输。权重和 activation 仍 BF16，没有 FP8 权重量化、预量化权重接入或 FP8 GEMM。
- 历史完整 CPU 为 995 passed/73 skipped；本地 TP bulk/部署/FP8 core 专项为 21 passed。CPU/Gloo 交接使用模型执行替身。历史性能仅有 BF16 chunk 共置四副本的短/长/混合各 32 个成功请求，没有 TP2/PD/FP8 加速结论。
- 当前租机数据盘任务目录 `/root/data/zincion/ai-infra/l40s-20261117` 已实际运行四张 L40S，52 CPU、约 468 GiB 内存；旧 `/Data2/...` 路径仅作兼容链接。原无卡 CPU 预算失败和 30 秒补充检查保留为历史，不能与本轮 GPU 混写。
- BF16 双卡 1P1D 的六组有效 KV 字节一致，生成、分页、并发与取消回收通过；FP8 KV TP1 六组输出一致但默认 FP32 prefill 很慢。四卡 TP2 P＋两个 TP1 D 实际运行后，修复后的组合仍有 chat-1 第 10 个输出分歧，独立 TP2 通过不代表该组合数值通过。
- 旧生成器和四卡 smoke 使用物理 GPU0/1/3/4 及旧 NUMA 假设，开卡后按现场设备适配。完整 campaign 控制器有已复现缺陷，不作为本轮前置；复用角色启动、比较和测量工具。

具体证据、文件名和旧环境边界集中记录在 [项目说明](../../docs/inference_optimization_overview_zh.md)，不反复生成指纹或审查快照。
