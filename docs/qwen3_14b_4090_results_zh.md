# Qwen3-14B 三卡 4090 阶段实测

GPU 0/1/2 各一个 TP1，BF16 权重。下表使用同一份 4096 输入、1024 输出请求清单，共享并发 4，各预热 8 条、正式 32 条，各组均成功 32/32。各对照批次独立启动。首二间隔为客户端第一、第二个输出事件之间的间隔。完整请求耗时包括收到末尾响应。中段长停顿指排除首二间隔与最后一个间隔后仍存在超过 500 ms 的间隔。

| 配置 | TTFT P50 / P95 (s) | 首二间隔 P50 / P95 (s) | 完整请求 P50 / P95 (s) | 输出 token/s | 有中段长停顿的请求 |
|---|---|---|---|---:|---:|
| Whole 共置 | 0.841 / 0.881 | 0.040 / 0.112 | 41.33 / 42.36 | 97.33 | 16/32 |
| Chunked 共置，预算 1024 | 0.911 / 1.376 | 0.039 / 0.041 | 41.44 / 42.53 | 96.78 | 2/32 |
| BF16 1P2D bulk，逐层对照轮 | 1.027 / 3.035 | 7.622 / 11.002 | 52.14 / 56.17 | 78.54 | 18/32 |
| BF16 1P2D 逐层 TCP | 2.004 / 3.858 | 0.212 / 1.972 | 43.43 / 46.47 | 91.54 | 0/32 |
| FP8 KV + query，1P2D bulk | 0.896 / 2.473 | 3.067 / 5.868 | 45.63 / 49.15 | 88.27 | 1/32 |
| FP8 KV + query，1P2D 逐层 TCP | 1.857 / 2.599 | 0.203 / 0.926 | 42.30 / 44.67 | 95.27 | 0/32 |

FP8 将每请求交接量从 640 MiB 减到 330 MiB，其中 scale 占 10 MiB。旧 FP8 bulk 的 float32 prefill 路径 TTFT P50 为 34.836 s，输出 41.32 token/s。切到 query 后，反量化的 K/V 转回 Q 的 BF16 精度参与 attention 点积。逐层组合相对同精度 bulk 的输出吞吐增加 7.93%，相对 BF16 逐层增加 4.08%。与 chunked 共置相比，输出吞吐低 1.56%。这些是同清单上的批次观测。

正确性抽查使用两条 4K prompt、C1 和两个 D。同轮逐层传输与新共置参考的 4 次对照均为 1024/1024 token ID 匹配。一条 prompt 与历史参考从第 4 个 token 起分叉，本轮 bulk 亦复现同一份新输出。C4 下组合方案与历史 FP8 bulk 完整文本相同 24/32；未做任务级质量评测。

## 传输后端与配比

同轮 BF16 逐层 socket TCP 和 Mooncake TCP 分别为 93.15 和 83.59 输出 token/s，结论限于本机 TCP 接入。入口 FIFO 试验使用 4 个活跃位、4 个等待位、30 秒等待上限。配置项为 `admission_queue_size` 与 `admission_wait_timeout_s`，前者默认为 0，复现实验时须显式开启。

FIFO 配比试验覆盖 4K/1K、1K/4K，各有三条成对回放的固定时间线，每条重复两轮，合计 192/192 成功。BF16 逐层 1P2D 的 TPOT P50 在 12/12 次配对中更低。4K/1K 的达标请求/s 在 6 次配对中两组各赢 3 次。项目自定义达标条件为 TTFT ≤ 2 s 且生成中段无 >500 ms 停顿。

## 复现边界

4K/1K 主表与 FP8 组合验证沿用快照 `019bd2f`。入口 FIFO 使用提交 `ba3c20f`，到达时间线实验使用 BF16。主表、FIFO 配比实验及 Mooncake 后端实验分别保留原始工作负载、启动参数、统计脚本和逐请求记录。主表未验证 FIFO、FP8 与逐层传输三者全开后的性能。
